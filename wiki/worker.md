# Worker (`worker/`)

Cloudflare Worker API named `awwworker` (entry `worker/src/index.ts`, itty-router v5). It backs the contact form, CMS auth, image uploads, and CMS blob storage. See [architecture.md](architecture.md) for where it fits.

## Endpoint map

| Method/Path | Handler | Auth | Notes |
|---|---|---|---|
| `GET /` | health check `"AWWW Service is running ..."` | none | |
| `POST /contact` | `emailController` | none | sends contact email via Brevo |
| `POST /auth/login` | `loginController` | none | returns access token + sets HttpOnly refresh cookie |
| `POST /auth/refresh` | `refreshController` | none (cookie) | verifies refresh cookie, rotates both tokens |
| `PUT /upload-image?key=...` | `imageController` | Bearer JWT (`authenticate`) | `bucket.put(key, request.body)` |
| `GET /data?key=...` | `dataController` | none | `KV.get(key)` |
| `PUT /data?key=...` | `dataController` | Bearer JWT | `KV.put(key, JSON)` |
| `OPTIONS *` | CORS preflight | — | 204 |
| catch-all `ALL *` | 404 | — | |

Allowed `/data` keys: `["sponsors", "horses", "directors", "data"]`; the client only uses `data` (one blob). See [cms.md](cms.md).

`dataController` is registered with `router.all('/data', ...)` and GET vs PUT is split inside the controller; note the PUT path performs authentication twice (harmless duplication — see [gotchas.md](gotchas.md)).

## Conventions

- **Controllers** (`*-controller.ts`, kebab-case): take `Request`, return `Response`, use shared `jsonResponse` / `errorResponse` helpers from `utils.ts` so CORS attaches everywhere.
- **Services** as singleton classes with `public static instance` + `static startService(env...)`, initialized per request in `index.ts` (guarded). Services: `EmailService`, `ImageService`, `DataService`, `auth/JWTService`, `auth/LoginService`.
- **Auth middleware** `auth/middleware.ts` `authenticate(req)`: on failure returns a 401 `Response`; on success returns `void` — callers must check the return value (pattern used in `index.ts` for `/upload-image`, and inside `dataController`).

## Global error handler

`fetch` wraps `router.fetch` in try/catch. On error it:
1. logs to console,
2. best-effort sends an error-alert email via `EmailService.sendErrorAlertEmail(500, new Date(), error, request)`,
3. returns 500 with `Internal Server Error: ...`.

**Known bug**: `EmailService.getErrorAlertBody` calls `errorReportTemplate(status, timeStamp, message, ...)` but the template's signature is `(status, message, timestamp, ...)` — the `message` and `timestamp` arguments are swapped in error-alert emails. See [gotchas.md](gotchas.md).

## Storage

- **KV** binding `KV` (namespace id `b67fbdf7a16144b582f05de578490f56`): thin singleton wrapper `DataService.fetchData`/`putData`; stores JSON strings; the whole CMS blob is kept under key `"data"`.
- **R2** binding `IMG_BUCKET` (bucket `aww-images`): `ImageService` uploads only (`.put`); reads happen via the bucket's public `r2.dev` URL on the client (`VITE_CDN_HOST`).
- **Email (Brevo)**: `EmailService` hits `https://api.brevo.com/v3/smtp/email`. Contact submissions go to `ADMIN_EMAIL` (+ `OWNER_EMAIL` when `DUAL_NOTIFICATIONS.js` is generated by `wrangler types`, not handwritten) — do not hand-edit.
- `worker/src/utils.ts` — `jsonResponse` / `errorResponse` / `getCorsHeaders` helpers; note an unused `import { get } from "http"` artifact at the top (nodejs_compat leftover).
- `worker/src/types.ts` — only `EmailRequest { email, name, message }`.
- `worker/src/templates.ts` — `contactSubmissionTemplate`, `errorReportTemplate`.
